# Rocky — the live demo plan

24 September 2026. How to show Rocky on a live CloudLabs lab using only what exists today.

This is the second version. The first was reviewed by four independent sceptics against the
source, the release gates and the recorded traces, and they refuted the claim the whole demo was
built on. What changed is listed first, because a demo plan that hides its own corrections is
the thing this product exists to prevent.

Every capability claim carries a tag:

- **MEASURED** — seen on the live portal, or present in a recorded trace, *doing this exact thing*.
- **GATED** — a release gate proves it, in a real browser against a test page, or in Node.
- **REHEARSE** — it should work; nobody has seen it on the page the demo uses. Run it first.
  If it is not green in rehearsal, cut it.
- **DO NOT SHOW** — it would mislead the room or fail on stage.

---

## What the review changed

1. **Nobody has watched a Purview step complete.** The recorded `list-grew 0 → 1` I called
   "after Create policy" followed a click on the *Policies* menu item, 894 ms after the portal
   announced "0 items" — the empty grid rendering its header row. No Create, Save or Submit has
   ever been recorded on Purview. The completion beat is REHEARSE, not MEASURED, and Lab Doctor's
   one "observable" step on that trace is a false positive that must be presented as such.
2. **The Create-policy Submit is at the end of Task 3, not Task 2** — roughly eleven wizard
   pages. The wizard must be pre-positioned on its final page before the room comes in.
3. **The "STUCK?" ladder will fire in every version of the demo**, including the 2-minute one.
   Three clicks on anything not glowed, or four route changes in a session (never reset), and an
   orange "STUCK?" card appears and recurs every 20 seconds. Filling the wizard is three clicks;
   Home → IRM → Settings → Indicators → Policies is four routes. This is the number-one blocker
   and it needs a code decision (below).
4. **The scripted refusal beat is unreachable once a guide is loaded.** "Which step am I on?"
   is answered from the believed step — *"It says: Select Create policy > Custom policy."* — with
   the number only when confidence is at least 0.80. That is honest, and it is demonstrable, but
   it is not "I can't tell yet." The beat is rewritten as *the step, not the number*.
5. **The `Client Error` permission message was measured on Purview's Users page, not Azure.**
   The Azure failure beat is cut; Azure is perception and honesty only.
6. **The failure channel was validated with a synthetic node, not a real error.** GATED, not
   MEASURED. Real errors on either portal are REHEARSE.
7. **The misclick call-out is not spoken on the guide-reader path** and each wrong click moves
   the ladder closer. DO NOT SHOW.
8. **"He says whose fault it is"** is true of the permission diagnosis only. The conflict message
   names no culprit. The line moves to the permission beat.
9. **The 0.95 is not a measurement.** It is the confidence Position assigns to any drawn
   `aria-current`. What was measured is that six Purview routes declare it. And inside the
   Create wizard, Position still reads the buried left-nav item and says "Policies".
10. **The belief has never moved off −1 in any Purview recording.** The glow following the step
    is GATED in Node mocks and REHEARSE live. Place following is measured; step following is not.
11. **A stored Foundry bundle makes content.js print "Step N of M" on Purview** from an unrelated
    lab's counter. The demo needs a fresh profile.
12. **The role-group classifier fix made today changes what Rocky says on the demo page.** On
    Policies, Purview may announce *"You currently aren't assigned to a role group that allows you
    to view alerts"* to an account with the IRM Admins role but not Investigators — and Rocky now
    diagnoses that as a permissions problem, on page load, before anything has failed. The demo
    account needs both role groups, or that sentence opens the demo.
13. **"What have I done so far?" never reaches the model.** It matches none of the deterministic
    question patterns, so the CloudLabs documentation corpus answers it — an article about ARM
    templates, scoring 2.81 against a 1.8 floor — under "MY BEST GUESS", and the code returns
    before the model is ever called. The 467-character grounding block is irrelevant to that
    question. Every typed accomplishments beat is cut; the proactive teaching moment is the only
    route by which "what did I accomplish" reaches a learner today.
14. **`webext/lab.json` is a committed Foundry QA fixture.** Rocky fetches it from the package,
    so on Purview "which lab is this?" answers `foundry-develop-ai`, resource group
    `ODL-AZURE-912345`, a contoso UPN — confidently, with a source — and every model answer is
    grounded on that fabricated identity. It must be replaced or blanked before any non-Foundry
    demo.
15. **The stale-build row was backwards.** A browser restart reloads content scripts but *not*
    the service worker, and `background.js` (the system prompt) changed today. Without `--fresh`
    the ask box runs yesterday's 110-word chatbot prompt while every content-script check is
    green. `--fresh` is mandatory, and it also removes the stored-bundle risk.
16. **Azure live regions have never crossed the frame boundary in a recording.** The Azure trace
    carries three clicks from the `reactblade` origin and no world event of any kind. "Clicks and
    live regions" becomes "clicks".
17. **The live completion path is tick-to-tick, not baseline-against-action.** The relay diffs
    list counts every second; the Completion Engine's `baseline()/changes()/verdict()` API is
    gated but has no caller outside its own file. The deep-dive slide must say so.

## The answer first

**Lab:** Microsoft Purview, the Zava "Know Your Data" lab, **Challenge 4 — Insider Risk for
Departing Users**. Browser only, no PowerShell, none of the tenant settings a fresh tenant ships
switched off, a place signal the portal declares on every page, and the guide Manoj owns.

**The moment the demo is built around — tagged honestly:** the wizard is already on its final
page. The learner clicks Submit. The success notification appears, the policies list gets one
longer, and Rocky says *"That went through — the list went from 1 to 2. Next, …"* Rocky did not
read that from the guide. He watched the portal do it. **REHEARSE.** The Completion Engine has
fired on this page's list during navigation; it has never yet been watched after a Submit. Record
one real Submit with the recorder the day before, and tag the beat by what that trace shows.

**The blocker that decides whether this demo can run at all:** the stuck ladder. Either approve
the feed fix below before rehearsal, or plan for an orange "STUCK?" card during the wizard.

**Positioning:** *Rocky is the lab mentor who was in the room.* Not a chatbot you describe your
screen to; a mentor who watches the portal with you, knows where you are, says what actually
happened, and never claims something he did not see.

**The one line:** *"A chatbot knows what you tell it. The lab guide knows what should happen.
Rocky knows what did."*

## The blocker: the stuck ladder

`world-model.js` decides the learner is stuck when `attempts >= 3` — and every click on anything
Rocky has not glowed is an attempt, reset only when the step index moves — or when `routeChanges
>= 4`, which is incremented on every URL change and **never reset anywhere**. After that,
recovery speaks rung 1 (*"This one takes people a minute…"*) under a "STUCK?" chip, then rungs 2,
3 and *"I AM STUCK TOO"* at 20-second intervals, restarting after each step advance.

On the demo path: filling three wizard fields is three attempts; navigating from Home to Policies
is four routes. The ladder fires in the 2-minute version.

**Options, for Manoj to choose — this is a code change and today's instruction was to stop
building:**

- **A. Fix the feed (recommended, ~1 hour with gates).** Reset `routeChanges` when the step
  advances, as `attempts` already is. Count an attempt only when a glow exists to miss — a click
  with nothing glowed is not evidence of anything. Both changes are what the recovery header
  already says the feed should do; they are corrections, not features.
- **B. Run without it.** Expect the card at the wizard's third click. Narrate: *"That is Rocky's
  patience running out — three rungs and he stops."* It is true. It is also the extension
  announcing its state in capitals during the showpiece.

Separately and smaller: the rung-0 diagnosis — the best sentence in the codebase — is delivered
under the same "STUCK?" chip. A one-word label change; also needs the go-ahead.

## Task 4 — Rocky's role

**AI Lab Mentor.** A mentor sits beside you, watches, says what they see, and lets you do the
work. That is what the code enforces: point, do not click; observe, do not assume; admit, do not
guess. Say "mentor" and the restraint reads as character rather than limitation. Not "coach"
(motivation), not "instructor" (authority), not "companion" (a pet), not "guide" (the lab guide
already is one).

## Task 6 — against AI Fellow–style mentors

Taking "AI Fellow" as the archetype — chat-first, curated knowledge, coaching voice, memory of
the person, no view of the screen. Present Rocky honestly; do not attack.

**Stronger:** Rocky sees the portal, in every frame; "did it work?" has an evidence-based answer;
Rocky refuses to guess a step or a cause; Rocky catches the *lab's* defects, not only the
learner's; Rocky's knowledge of a lab comes from walking that lab.

**Different, not better:** a companion to the guide, not a replacement; restrained by design, so
it speaks less.

**Weaker today, say it if asked:** conversation depth and memory across sessions; explanation
depth on labs without authored notes; polish.

**Emphasise:** *the mentor who was in the room* versus *the mentor who was told about it
afterwards.* Never claim conversation.

## Final answer

*If you had to convince a room of executives and technical decision makers that Rocky is
groundbreaking, using only what exists today, exactly how would you run it?*

1. **Decide the stuck-ladder fix first.** Without it, the extension shouts "STUCK?" during the
   showpiece. It is an hour's correction to a feed the code already says is wrong.
2. **Record one real Submit on Purview before promising the completion beat.** Nobody has seen
   it. Tag the moment by what the trace shows, and if it is silent, the demo leads with the
   permission beat instead — which is real, recorded on this page, and the most common lab
   defect there is.
3. **Purview, Challenge 4, fresh profile, wizard pre-positioned.** Open on the moment, not the
   setup.
4. **Three beats: what just happened, what Rocky won't claim, where he can't place you.** The
   completion line is the product. The step-not-a-number is the trust. The Azure admission is
   the character.
5. **For the technical room, end on Lab Doctor — including its false positive.** "We know
   exactly where it over-reports" is worth more than a clean verdict nobody can check.
6. **Say the limits before they ask.**
7. **Close on one line.** *A chatbot knows what you tell it. The guide knows what should happen.
   Rocky knows what did.*

Do not show the misclick call-out, the duplicate-name error, any Azure error, Azure completion,
Azure place as a capability, the Foundry mock, Copilot Studio or M365. Do not promise the
"what if I skip this" line. Do not say the glow follows `aria-current`. Do not type "what have I
done so far?" or "which lab is this?" into the ask box — the first goes to the docs corpus, the
second to a committed QA fixture. Do not run the demo on a persisted profile.
