Floating-hands rig & gesture library

Detached EVE-style mitts that trail the body via per-hand springs — never a limb. The live build already carries seven gesture slots wired to setEmotion(); this locks their geometry, timing, easing, and secondary motion so hands and eyes stay one creature. Lineage: EVE / BD-1 / Cozmo detached hands; Thomas & Johnston overlapping action; Dragan & Srinivasa legible deixis.

Secondary motion — the spring that makes it alive

Each hand runs a semi-implicit spring trailing the body's smoothed position. This is the overlapping-action / drag layer — hands arrive a beat late and overshoot ~3% before settling, exactly like the panel spring. The build already does a velocity-lag approximation (lagX = −vel.x·6); upgrade it to a true spring per hand.

handSpring() — per hand, per framedrop-in
// constants — same family as panel-open (settles ~320ms, ~3% overshoot)
const STIFF = 220, DAMP = 26, MASS = 1;
// target = gesture wrist + velocity-skew + counter-rotation on turns
const skewX = clamp(-bodyV.x * 0.06, -16, 16);  // drag opposite travel
const skewY = clamp(-bodyV.y * 0.06, -16, 16);
const counterR = clamp(-bodyV.x * 0.5, -12, 12); // wrist tilts against turn
const tx = wrist.x + skewX, ty = wrist.y + skewY;
// semi-implicit Euler — stable at 60fps
const ax = (STIFF*(tx - h.x) - DAMP*h.vx) / MASS;
const ay = (STIFF*(ty - h.y) - DAMP*h.vy) / MASS;
h.vx += ax*dt; h.vy += ay*dt;
h.x  += h.vx*dt; h.y += h.vy*dt;
h.r   = damp(h.r, wrist.r + counterR, 9, dt);
  • Phase offset. Drive the two hands' idle float and any loop π radians apart so they never pump in lockstep — reads organic, not mechanical.
  • Draw order. Hands render behind the body at rest; promote to in front when lifted above y < −30 (celebrate, wave, point), so the lifted hand reads clearly over the visor.
  • Reduced-motion path. Under prefers-reduced-motion: reduce, drop the spring and skew — snap hands to the static gesture wrist with a ≤120ms opacity/position fade. No overshoot, no idle float.
Consistency check All seven names already exist in the build's GEST table and E emotion map (g:'rest'|'wave'|'think'|'celebrate'|'investigate'|'palm'). This addendum only renames the data-driven slot to point-at-target, adds the true per-hand spring, and pins finger/thumb states + per-gesture timing — no new wiring required.

Guardian hero — from villain cues to protector

The original hero preset stacked four antagonist cues at once: red glow, narrowed eyes, inner-raised angry tilt, sharp corners. We invert each. Round + tall eyes, near-neutral outer tilt, soft corners, and a cool teal→blue glow read trustworthy and protective, not menacing. The live build already moved hero to a blue arc-eye; this finalizes the exact values, aura, hand pose, entrance, and copy.

  • Eyes-only fallback. Where no hand layer is active, express the open-palm read through the steady upward gaze + halo reaching slightly toward the viewer.

03

Double-click easter-egg catalog

Single-click stays sacred — it opens the panel. Double-click is the play gesture. Eight canvas-feasible reactions across three tiers, built from three shared primitives: a freeze-frame helper, a damped-spring / overshoot easing, and a particle-burst emitter. Grounded in Vlambeer screenshake juice, Disney's 12 principles, eyes-as-emotion acting, and the Clippy anti-annoyance lesson.

Global guardrails — apply to all

  • Never during real help. Hard-suppress every reaction while the panel is open, a request is in flight, or text is streaming. Play is for idle moments only.
  • Cooldown + cap. 8–10s minimum between reactions; max ~4 per 10-min window. After 2 rapid double-clicks, one "okay, okay" annoyed-eye beat, then ignore further double-clicks for 15s.
  • Weighted-random, no immediate repeats. Never the same reaction twice in a row; keep Tier-3 genuinely rare so they stay special.
  • Always self-recover. Each reaction returns Rocky to neutral idle within its stated duration — never stays broken, off-screen, or upside-down. Clamp all knockback/float to canvas bounds.
  • Reduced-motion. Under prefers-reduced-motion: reduce, swap shake / spins / large translations for a static eye-state + the line in a bubble. Satisfies WCAG 2.3.3, keeps the personality.

Honest in-browser awareness

The honest verdict up front: an in-page companion can observe the user's interaction with Rocky's own page/tab and the DOM it can legally see — and nothing else. Not other tabs, windows, the desktop, other apps, or a cross-origin iframe. The sandbox + same-origin policy are a hard wall. Each richer tier costs a permission prompt, an install, or a deployment — and real privacy debt.

But contextProvider.js is effectively a T3 source already (lab progress / validation-results / activity-log from the CloudLabs API). T3 is Rocky's most powerful and least privacy-fraught channel. In-page proactive-detection ruleset — ship now, T0 + T3

awareness state machine — evaluate on 1s tick + on eventsT0 / T3
SIGNALS (rolling state)
  lastActivityTs     ← reset on pointermove/keydown/scroll/click/input
  hiddenSince        ← set on visibilitychange→hidden, clear on visible
  domErrorSeen       ← MutationObserver / window.onerror / unhandledrejection
  clickHistory[]     ← {selector, ts} ring buffer (last ~20)
  scrollReversals    ← direction flips in last 5s
  lastStepValidated  ← from T3 contextProvider (validation-results)
  copyEventOnError   ← copy fired while an error node is visible

RULES
1  INACTIVITY     if now-lastActivityTs > 90s && visible && !cooldown
                  → soft "still there?" bubble; escalate gently at 4–5min
2  RETURNED       on →visible: <20s say nothing · 20s–5min light re-orient
                  · >5min recap + current validation state (pull T3)
3  ERROR          on domErrorSeen: debounce 2s, offer help referencing the
                  error text Rocky can actually read. Never claim cross-origin.
4  STUCK          if now-lastStepValidated > 4min (T3 truth) && activity present
                  && (scrollReversals high OR repeated same-selector clicks)
                  → "step N being stubborn — want a hint?"  // strongest signal
5  THRASH         if same selector ≥3× in 15s OR form re-submitted ≥2× → error
                  → "that keeps bouncing back — let's check X."
6  DEBUG TELL     if copyEventOnError → offer to explain the copied error category

GLOBAL GUARDRAILS
  per-rule cooldown 60–120s + global max N nudges/session (attentive, not naggy)
  pause 60fps loop + timers on hidden (battery; rAF throttled while hidden anyway)
  every line dismissible; degrade silently if a signal source is unavailable
Stays roadmap — real trust escalations, not just engineering T1 extension: "read your browsing history / data on all sites" warning, store review, per-browser. T2 screen capture / CV: getDisplayMedia() forbids silent capture, can't persist the grant, re-consented every session by spec; native agents add max install friction. Avoid IdleDetector as a dependency — Chromium-only, prompted, Mozilla + WebKit call it surveillance-grade; use the DIY heuristic, reach for it only as opt-in progressive enhancement. Don't chase awareness via T1/T2 that you can get more cleanly from the T3 telemetry Rocky already has wired.
