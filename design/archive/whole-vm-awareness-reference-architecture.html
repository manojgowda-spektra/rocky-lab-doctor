01 Executive summary & thesis

A first-party agent on the VM beats every alternative — and the perception order is the product

Rocky's job is to know what the learner is actually doing on a Windows lab desktop — which Azure Portal blade, which command, which error — and to nudge precisely, rarely, and only when it earns the right. The whole architecture rests on one ordering principle: structure before pixels, cheap before costly, on-VM before cloud.

The thesis, in one line

An agent baked into the CloudLabs Windows image — reading the desktop through the OS accessibility tree, reasoning in-tenant, drawing an overlay the learner sees in the RDP stream — is categorically better than watching from the browser, a DOM extension, or screen-scraping the RDP pixels.

Why it's decisive

  • Semantics, not pixels. Only on-VM code can ask the OS "what control has focus, what's its value, did a modal open" — getting typed structure the browser and the RDP frame have thrown away.
  • Privacy leverage. Redaction runs before anything leaves the VM; pixels never have to be the egress.
  • Control of the image. CloudLabs owns the build, so Rocky can force-enable browser accessibility, ship a shell-integration side-channel, and sign its own binary into the base image.

02 Perception stack

Five tiers, walked top to bottom — never skip ahead, never poll the tree

Unusually, the cheapest path is also the most accurate and the only one that returns actionable handles. So the rule is fall through, never jump. Each tier escalates only when the one above returns nothing useful — proven by a concrete signal, not a vibe.

0Platform

Cosmos lab telemetry guide / step / validation / deployment_activity_log

Already-structured lab context with no screen at all — which step, did validation pass, what did the deployment log say. The P1/P2 backbone; zero new egress. Answers "what should be happening."

escalate when on-screen state is needed, not in the lab record

1WinEvent

Win32 foreground + SetWinEventHook out-of-context · sub-ms

GetForegroundWindow → PID → process image (chrome.exe / Code.exe / WindowsTerminal.exe / mmc.exe), plus title & class. EVENT_SYSTEM_FOREGROUND, EVENT_OBJECT_FOCUS, DIALOGSTART, ALERT as cheap async triggers. The top-level state machine: "which app, did something appear."

on a trigger, resolve the hwnd/point into a UIA element for detail

2UIA

UI Automation — scoped, cached read IUIAutomation6 (COM) · CacheRequest

The primary rich lens. ControlType, Name, AutomationId, BoundingRectangle (feeds the overlay's pointing), patterns (Toggle / Value / Window.IsModal / Selection / TextPattern), and reactive events (focus / property / structure-changed / window / notification). Never walk-and-read live — scope a CacheRequest to the focused subtree on a dedicated thread.

escalate ONLY on a concrete UIA failure signal — empty/opaque tree, blank value where text renders, rect/point mismatch

3OCR

On-device OCR of a cropped region Windows.Media.Ocr · WGC capture

For custom-drawn / GPU / DirectX surfaces, installers, terminals, transient toasts — anything with no provider. Capture via Windows.Graphics.Capture (sees the GPU path; BitBlt comes back blank for browsers), OCR in-process on the VM at $0, zero egress. Returns text + boxes, not handles.

escalate when OCR text is incoherent, or the question is "where am I / what can I do here"

4VLM

Vision-language model on a redacted crop in-tenant · ~0.7–4s · $0.004–0.02+/frame

For charts/diagrams, holistic "what's on this screen" reasoning, and incoherent-OCR cases. The most expensive, highest-latency, most privacy-toxic tier — redacted & in-tenant only, behind confirmation. Gives understanding but only approximate coordinates. Whole-frame screenshots are disallowed in steady state.

Color encodes posture: green = structured/free/safe → teal = on-VM rich → amber = costly fallback → red = exceptional & gated. The gradient is ADR-002.

Which signal detects which condition

Which app

EVENT_SYSTEM_FOREGROUND → PID → image name, corroborated by class/title. Cheapest, most reliable; the top-level state machine.

Current task / step

UIA focused element + Content-view ancestors (which blade/tab/dialog/field) + window title; fuse focus + structure events to track step transitions.

Error / dialog appeared

WindowOpenedEvent + Window.IsModal; DIALOGSTART/ALERT triggers; UIA notification when apps push it. On web, structure-change + read text — UIA won't type it as an error.

Stuck

A temporal/negative signal: no focus/structure/value/text events for N seconds while the same step is focused; repeated identical structure cycles; a modal that stays open. Built from event timing, not a single API.

Wrong portal / region

Browser title + Azure Portal breadcrumb/blade Names vs. expected step; address-bar Edit element's Value for URL; VS Code open-folder vs. expected.

Command failed

TextPattern gives the text but no exit code. Prefer a shell-integration side-channel — $LASTEXITCODE, Start-Transcript, OSC 133 prompt markers — far more reliable than scraping.

Two honest weak spots — design around them now

1 · Web-content semantics. The two highest-value targets (Azure Portal, VS Code) are both web-rendered. Native UIA arrived by default in Chrome/Edge 138 (2025), and since CloudLabs owns the image Rocky can launch the browser with --force-renderer-accessibility so the DOM is always perceivable. But UIA is a semantically weaker lens for web than IAccessible2 — it mismaps ARIA, ghettoizes roles, and won't reliably type validation errors. Plan an IAccessible2 adapter for richest web data, and for browser-hosted blades expect OCR/VLM to carry real load, not just "fallback."

2 · Terminals. TextPattern gives the visible buffer but zero command semantics. Ship a shell-integration side-channel in the image (transcript / exit codes / OSC 133) instead of scraping the screen for "did the last command error."

03 On-VM agent + RDP / overlay

A service for lifecycle, a per-session UI process for perception and the overlay

One fact inverts the obvious design: RDP-over-browser means the RDP client is server-side. There is no mstsc.exe on the learner's machine — the realistic backend is Guacamole guacd + FreeRDP. That kills the clean DVC plug-in path and makes an outbound agent→cloud WebSocket the right v1 comms.

Why the "obvious" DVC path is the harder one

Microsoft's clean Dynamic Virtual Channel APIs (IWTSPlugin, registered under HKCU\…\Terminal Server Client\Default\AddIns) are client-side plug-ins for the native RDC / mstsc client — which doesn't exist in a browser-delivered session. A DVC here would have to be a compiled FreeRDP add-in inside guacd, and FreeRDP exposes no documented runtime API to register a custom channel. So DVC is possible but it is platform-team surgery on the remoting tier. Recommendation: outbound WebSocket as v1; defer DVC as a later egress/latency optimization. The WebSocket choice is deliberately backend-agnostic, so it holds even if the backend is DCV or Windows 365.

Overlay rendering — tractable, and it must not hook

RDP streams whatever is composited on the VM desktop, so a top-most window on the VM is automatically in the captured frame — no client-side rendering needed. The recipe is a layered, click-through window:

// always-on-top, per-pixel alpha, click-through, never-activate
WS_EX_TOPMOST | WS_EX_LAYERED /* UpdateLayeredWindow, per-pixel alpha */
            | WS_EX_TRANSPARENT /* opaque avatar pixels also pass clicks through */
            | WS_EX_NOACTIVATE;
// alpha-0 pixels pass the mouse automatically; one carved-out hittable handle = "chat"
// declare Per-Monitor-v2 DPI + handle WM_DPICHANGED — browser RDP resizes constantly

Click-through by construction

Alpha-0 pixels pass the mouse automatically; WS_EX_TRANSPARENT makes even the opaque avatar click-through, so Rocky never blocks a lab control — except one deliberately hittable "chat" handle.

Zero injection — and it must be zero

Game overlays prove always-on-top companions are wanted, but DLL injection + Present() hooking is indistinguishable from cheats/malware. Rocky renders top-most with no hooking — and must, or the image's own EDR/AV quarantines it.

Service can't draw (Session 0)

The documented MS pattern — service + separate user-session GUI app + IPC + CreateProcessAsUser — is exactly the process split above.

The honest input limit

Pixels travel in RDP video, but input handling is local Win32. The on-VM agent observes and advises; "Rocky clicks for you" needs a separate, consented action path (deferred to P4).

Packaging into the image

A thin signed binary baked into the CloudLabs base image; the brain stays in the cloud. Context fuses a redacted screen summary with CloudLabs guide/validation APIs via a lab-scoped least-privilege token. Updates are signed and authenticated with rollback across the fleet. This design makes the in-VM tier buildable but does not by itself lower the high-risk rating — telemetry-only mode, consent/disclosure, redaction, and the enterprise character-off skin are build gates (Part 6).

04 Vision / OCR fallback

The exception tier: triggered by a signal, capped by a budget, redacted before it leaves

Vision is genuinely necessary — for custom-drawn / GPU / DirectX surfaces, installers, and apps with no provider — but it is the slowest, costliest, most privacy-toxic tier. The discipline is two rules: escalation is triggered by a concrete UIA failure, not a guess; and redaction happens before encode, OCR before network.

Capture, on the VM

Default to Windows.Graphics.Capture (WGC), not BitBlt. BitBlt is blind to GPU rendering — browsers come back blank — while WGC does GPU-path capture, supports per-window capture (TryCreateFromWindowId), can drop the cursor (IsCursorCaptureEnabled), emits change hints (DirtyRegions), and returns black frames for DRM/protected content — a privacy feature for a tenant agent. Policy: active-window-only, event-driven, never desktop streaming. BitBlt is kept only for occluded-window cases.

OCR / VLM selection & the cost model

Windows.Media.Ocr — tier-2 workhorse

Already on the image, in-process, $0, zero egress. Tesseract as a same-machine escalation; Azure AI Vision Read (~$1.50/1k transactions) reserved for document-grade extraction, redacted & in-tenant only.

VLM token math (planning)

Claude: ⌈w/28⌉×⌈h/28⌉ → a 1080p frame ≈ 2,691 visual tokens ≈ $0.0135 image-only at Opus 4.8 ($5/1M in). GPT-4o tile model 85+170×tiles → ~1,105 tokens ≈ $0.0028 at $2.50/1M.

Per-invocation ladder

UIA ~1–10 ms / $0 → on-device OCR ~35–95 ms / $0 → VLM ~0.7–4 s / $0.004–0.02+. The bankruptcy axis is events × frequency, not unit cost.

Six frequency / triggering rules

  1. UIA-first — never invoke vision when the tree answers.
  2. Event-driven, not polling — capture on a trigger, never on a timer.
  3. OCR before VLM — cheap text extraction before model reasoning.
  4. Crop, then encode — send the smallest region, not the frame.
  5. Perception caching — diff against the last snapshot; unchanged → no call.
  6. Budget & degrade — a per-session token cap; degrade to OCR/structured when exhausted.

Capture + redaction pipeline

1 CROP      active window / region only (never the desktop)
2 MASK      black out password/credential fields using the UIA rects you do have
            + a local PII pass (email / token / card / connection-string patterns)
3 OCR       on-device, in-process — extract text + boxes  (network not yet touched)
4 CLASSIFY  if text resolves the question → done, no model call
5 VLM       only if still opaque → in-tenant model on the redacted crop
6 RECONCILE map model output back to a UIA element where possible (for a real handle)
7 ACT       behind confirmation; destructive actions require human-in-the-loop

Invariant: redact before encode, OCR before network. OCR gives text+boxes not handles; VLMs give understanding but approximate coordinates — turning either into a safe action is a separate, error-prone step. All figures are order-of-magnitude, to validate on the real CloudLabs image.

05 Reasoning & context fusion

A typed snapshot, an on-VM pre-filter that rejects 90%+, then a gated cloud call

The reasoning spine is built around change: every perception event becomes a versioned snapshot carrying a delta from the last one, a quiet pre-filter does free-to-cheap triage on the VM, and only the ambiguous tail — minimized and redacted — reaches the cloud LLM, constrained to a structured action.

Context schema — the ContextSnapshot

Produced on-VM per fused event, versioned, with provenance and confidence on every node so the reasoner trusts UIA over OCR on conflict, and a prev_snapshot_id + delta so every stage reasons about what changed (which is also the prompt-caching strategy).

{
  "v": 2, "snapshot_id": "s-8842", "prev_snapshot_id": "s-8841",
  "focus":   { "app": "AzurePortal", "surface": "web" },         // app + surface type
  "ui":      [ { "role":"combobox", "name":"Size", "state":"open",
                 "source":"uia", "confidence":0.98 } ],  // salient nodes, scoped not full-tree
  "events":  [ "focus→Size", "structure_changed" ],            // ring buffer
  "vision":  null,                                          // only when escalated
  "lab":     { "step": 4, "objective":"create_vm", "last_validation":"fail:region" },
  "derived": { "salience":0.7, "signals":["on_step","dropdown_open"] },
  "delta":   { "changed":["ui[0].state"], "since":"s-8841" }
}

Structured actions — the output schema

AgentAction = // the model must emit exactly one of these

  | { "kind":"speak",           "text":"…" }

Two-scope memory (session + learner profile) tunes thresholds without changing rules. The pre-filter is tuned toward silence to avoid Clippy-spam — so it will sometimes miss a welcome nudge; the un-throttled pull affordance is the deliberate pressure valve covering that gap.

The honest UIA caveat carried through reasoning

UIA-first is validated for native / WPF / WinUI, but breaks for browser-hosted targets — the Azure Portal and web SQL tools inside the VM are a DOM the VM-side UIA reads only weakly. There, OCR/VLM is the primary signal, not a fallback; the reasoner must not promise UIA-grade precision for those surfaces, and provenance/confidence on every node is what lets it degrade honestly.

06 Security, privacy & governance

Defense-in-depth, because the redaction filter will miss

Microsoft Recall shipped screen-capture-by-default in May 2024, drew a UK ICO inquiry, was pulled and re-architected — and even after relaunch, testers through 2025 showed its "sensitive information filter" still captured passwords, cards, and SSNs. The lesson is non-negotiable: on-VM redaction can never be the sole control. The model is structured-first, positive-allowlisting, minimization, fail-closed dropping, and a published drop-rate metric instead of a "we never leak" promise.

Threat model (STRIDE + LINDDUN + an egress lens)

The crown-jewel asset is whatever the learner can see or type — which on a cloud-admin VM includes live Azure tokens, ARM/Terraform secrets, connection strings, SQL customer data, and the learner's own PII. Four trust boundaries: B1 untrusted screen content → agent; B2 the agent→VM egress gate; B3 orchestrator→model; B4 anything→persistent storage.

A learner can deliberately show Rocky a secret; we protect against incidental and systemic capture. VM-image trust is a platform-level root.

Data-flow & the layered on-VM redaction pipeline

Design rule: minimize first, redact second, never let raw pixels be the steady state. Every stage runs on the VM before boundary B2. The agent emits a Perception Event carrying state, not values — region:selected, not the region name — unless that field is on the current step's allowlist.

Raw perception (UIA node / OCR text)
  1 ALLOWLIST GATE          keep only fields this lab step needs  (positive control — default-deny)
  2 CREDENTIAL-SURFACE       focused app is a password mgr / Hello / az device-login /
    SUPPRESSION             Key Vault blade / RDP cred dialog → emit "redacted: credential surface"
  3 PATTERN/ENTITY REDACT    Presidio-style on-VM NER + regex: JWT/SAS/PEM/connection-strings,
                            email/name/SSN/card(Luhn)/IP, subscription/tenant GUIDs → placeholders
  4 MINIMIZE                truncate to the smallest text that answers the step question
  5 SECOND-PASS CLASSIFIER   small on-VM model scores residual sensitivity;
                            above threshold → DROP (fail-closed) and log the drop count
  └─► Perception Event ──TLS──► orchestrator

Layer 1 (the allowlist) is strongest because it is positive ("only these fields"), where Recall's filter failed precisely because it was a negative content classifier. Layer 5 is the backstop: when uncertain, drop, don't send. The dropped count ships from day one — Rocky's honest "health report," a metric not a promise.

Inference & residency

In-tenant Azure OpenAI, region/DataZone-pinned, no-training, with ZDR / modified abuse-monitoring for regulated labs (no 30-day human-review store). On-VM small models do the high-frequency triage/redaction so most events never reach the cloud — privacy, cost, and latency all at once. No-training must be contractual, not just configurational.

Tenant isolation

Every call carries a server-validated partnerGuid + session pseudonym; the orchestrator refuses cross-partner joins. No shared context cache across sessions; each session's store is destroyed at end. Events carry session pseudonyms, never durable learner keys (defeats re-identification).

Consent UX — the Recall lessons, inverted

Recall did wrong

  • On by default, opt-out
  • Silent capture every ~5s, durable timeline
  • No always-visible capture indicator
  • "Sensitive info filter" relied on as the safety story — and it leaked
  • Hard to pause; local DB initially unencrypted

Rocky's requirement

  • Off by default, affirmative per-session opt-in (logged)
  • Ephemeral by default; no timeline without admin opt-in + disclosure
  • Persistent "observing" indicator, driven by the capture gate itself — can't lie
  • Redaction is defense-in-depth, never sole; visible drop counter
  • One-click pause/DND (auto-pause on credential apps); instant total disable

Escalation to richer perception (element-read / OCR / screen-share) requires a momentary explicit "Show Rocky this" and auto-expires. A "What did Rocky see?" transparency panel shows the live structured events, the running drop counter, current mode, and last egress. Staff shadow-mode observation is itself consented, indicated ("Instructor is viewing"), time-boxed, and audited — it never bypasses the learner indicator. Declining observation still leaves guide-aware Rocky working (graceful degradation, SC-001).

Governance checklist (what a buyer's security team will run)

Admin / tenant

  • Per-lab enable (off by default): observation: none|structured|escalation-allowed
  • Tenant kill-switch + policy defaults
  • Residency policy per tenant; on-VM-only mode for the strictest buyers
  • App-focus auto-pause allowlist

Data & inference

  • Ephemeral-by-default enforced in code; retention is opt-in + disclosed
  • Redaction with a measured drop counter; regression tests vs. a secret/PII corpus
  • In-tenant, region-pinned, contractual no-training; ZDR for regulated labs
  • Per-session token cap (BC-001, T11)

Audit & supply chain

  • Append-only, tamper-evident audit in a separate trust domain; never log content
  • Signed reproducible builds + SBOM + image-signing; least-privilege identity
  • Egress allowlist: agent talks only to the orchestrator
  • All observed content treated as untrusted data (T4)

Compliance mapping

  • SOC 2 Type II / ISO 27001 — scope observation into existing controls
  • GDPR — consent + legitimate interest, minimization, DSAR, DPA, DPIA
  • FERPA — school-official exception or de-identified session-scoped context
  • Preserve Microsoft SSPA / DPR posture (BC-002)

Open items needing CloudLabs Trust/Compliance confirmation (checklist B1/B2/B3): authoritative SOC2/ISO/FERPA artifacts, the exact Azure OpenAI deployment region/type, ZDR eligibility, and the real learner-PII inventory. This spec is the explicit ADR-004 gate: P3 does not ship until P1/P2 prove value and this model passes enterprise security review.

07 Comparable-product lessons

The recurring failure isn't perception quality — it's where the pixels go, and consent

Across eight product clusters — Recall, Copilot Vision, NVIDIA G-Assist, Apple onscreen Siri, UiPath/Power Automate, NVDA/JAWS/Narrator, game overlays, and the "invisible-assistant" class — the patterns converge hard. Rocky's in-tenant, CloudLabs-owns-the-image design can win on the exact axis these products lost on.

Do — earned by a product

  • Treat capture as a liability to minimize — Recall, the best perceiver, became 2024's most-attacked feature purely over where pixels went.
  • UIA-first with a CV/anchor fallback — RPA tools and screen readers both walk the a11y tree but ship CV fallbacks because selectors are brittle and IPC is slow.
  • Render top-most without injecting — Rocky lives in a composited RDP session; it can render with zero hooking, and must.
  • Copy Copilot Vision's consent template — explicit opt-in + "context cleared at session end."
  • Cap compute hard, reason off the hot path — G-Assist's local model tanked framerates to single digits.

Don't — proven to backfire

  • Don't store captures in the clear — Recall's unencrypted local SQLite, readable by any user-level process, was the core breach.
  • Don't DLL-inject / hook Present() — indistinguishable from cheats/malware; Discord re-architected to a non-injecting overlay in 2025; EDR/AV will quarantine it.
  • Don't be "invisible" — the Cluely/LockedIn class is defined by exam/interview cheating; that's the precise reputation a lab/enterprise tool must avoid.
  • Don't trust a single content filter — every "sensitive info filter" that was the safety story has leaked.
  • Don't re-walk the tree per frame — cache it; brittle selectors + slow IPC sink naive implementations.

Vendor self-descriptions (NVIDIA, Microsoft, Apple) are claims; the harder evidence is independent testing (Beaumont's Recall teardown, PC Gamer's G-Assist hands-on, UiPath/PAD selector-brittleness docs). Some Apple onscreen-Siri and Copilot Vision details are 2025–2026 announcements that have historically slipped — treat ship dates as soft.

08 Phased roadmap & trust gates

Earn each tier — value first, then the gate that unlocks the next

The phasing maps to a risk gradient (ADR-004): low → medium → high → highest. Each phase must deliver standalone value and clear an explicit trust gate before the next is built. No phase is a prerequisite spend with no payoff of its own.

P1

Shipping scope · low risk

Guide-aware Rocky — browser/telemetry only

Value: explains the current step, interprets validation pass/fails, answers lab-content questions — grounded in Cosmos guide/validation, no screen at all. Ships on near-existing capability. This is the on-ramp the rest depends on.

Gate ↓Proven unblocking value + grounded, non-hallucinating answers (PC-001) before adding any session signal.
P2

Committed scope · medium risk

Session-aware — telemetry event bus, still no pixels

Value: stall detection, precise proactive nudges, deployment-error help grounded in deployment_activity_log, session memory. Enabled by platform additions (Runtime Context API + event bus). The proactive ruleset (Part 5) runs on structured signals only.

Gate ↓Proactivity precision proven (low false-positive rate, ADR-003) and the Part 6 security model passes enterprise review — the explicit ADR-004 trigger to unlock P3.
P3a

On-VM MVP · high risk

On-VM agent — UIA structure only, overlay, no vision

Value: first true desktop awareness — "which app, which blade, which field, did a modal open" via UIA + WinEvents, with the overlay pointing at real BoundingRectangles. OCR/vision off by default. Proves the on-VM agent, overlay, comms, and redaction pipeline end-to-end on the cheapest, safest perception.

Gate ↓Drop-rate metric green on a secret/PII corpus; consent UX + un-spoofable indicator shipped; agent signed, egress-locked, SBOM'd.
P3b

Add the fallback tier · high risk

+ On-device OCR, then in-tenant VLM

Value: covers the gaps UIA can't see — custom-drawn surfaces, installers, browser-hosted blades where the web tree is thin, charts. Added behind the escalation rules (Part 4): OCR first (free, on-device), VLM only when OCR is incoherent, redact-before-encode throughout.

Gate ↓Per-session vision budget enforced; capture+redaction pipeline validated on the real image; cost/latency within BC-001 at workshop concurrency.
P4

Highest risk · deliberately last

Proactive multimodal & consented action

Value: Rocky can do more than point — with explicit, consented, confirmation-gated action ("Rocky clicks for you" via a separate input path, since RDP input is local Win32). Full multimodal fusion of structure + vision + lab context.

Gate ↓Human-in-the-loop for destructive actions; safety review of the action path; no high-privilege tools in the observation tier (T4). Unlock only after P3 trust is established in production.

09 Risks, unknowns & what to prototype first

The unknowns are concrete — and they sort cleanly into "prototype this first"

Open unknowns to confirm

?

The remoting backend

Guacamole/FreeRDP is the well-supported assumption, abstracted behind the launch URL — but it could be DCV or Windows 365. The outbound-WebSocket comms choice is deliberately backend-agnostic so it holds regardless.

?

Web-tree quality on the real image

How much the Azure Portal & web SQL tools actually expose via native UIA / IA2 vs. forcing OCR/VLM — decides how much load the vision tier truly carries.

?

Cosmos learner-facing agent runtime

ADR-006 assumes Cosmos can host a learner-scoped agent at lab-session scope; the exact extensibility of the tool framework is unconfirmed.

?

Real cost/latency & PII inventory

All cost/latency figures are order-of-magnitude planning numbers; the learner-PII inventory and ZDR eligibility need Trust/Compliance confirmation (B1/B2/B3).

Prototype in this order

  1. UIA reader on the real CloudLabs image

    Cached, event-triggered read of the Azure Portal + VS Code + a terminal. Measures the single biggest unknown — web-tree quality — at near-zero cost.

  2. Click-through layered overlay in an RDP session

    Prove the window composites into the browser-delivered video, passes input through, and survives WM_DPICHANGED on resize.

  3. On-VM redaction pipeline + drop counter

    Run the 5-layer pipeline against a secret/PII corpus; publish the drop rate. This is the artifact the security gate turns on.

  4. Outbound WebSocket → Cosmos agent round-trip

    A typed Perception Event in, an AgentAction out, with the four-step gate and structured outputs — end-to-end on cheap models.

  5. WGC capture + on-device OCR escalation

    Only after 1–4: prove GPU-path capture + Windows.Media.Ocr on a custom-drawn surface, behind the escalation trigger.

The decisive bet, restated

A thin, signed, least-privilege agent in the image — perceiving structure-first and vision-last, reasoning in-tenant behind a quiet gate, and rendering an un-spoofable, click-through overlay — is the only design that delivers whole-VM awareness and survives an enterprise security review. The capability and the trust model are not separable; this document specifies both, and the roadmap earns them in order.
