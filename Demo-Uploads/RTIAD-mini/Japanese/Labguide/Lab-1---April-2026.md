# シナリオ / 問題の説明

Fabrikam Inc. は、ノベルティ商品の卸売業者です。同社はオンライン プラットフォームを通じて世界中の小売顧客と取引しており、新たな国際市場でプレゼンスを高めることを計画しています。Fabrikam は、再販業者と協力して Rapid Delivery Service の新しいパイロットを立ち上げたばかりで、顧客はニューヨーク市で購入した商品を 2 時間以内に受け取ることができます。Fabrikam は複数台の配送トラックを活用して、注文があった商品を再販業者から集荷し、顧客に届けます。

分析エンジニアであるあなたは、運用チームが注文を納期に間に合うように処理できるように、および経営幹部が最新の情報に基づいて意思決定を行うことができるように、各チームにリアルタイムの分析情報を提供することを求められました。

**現在の課題**

- eコマースの Web サイトから次々と継続的に入ってくるリアルタイム データや、配送トラックの配置を管理する、堅牢かつスケーラブルなアーキテクチャを開発すること。eコマースの Web サイトでは、Azure イベント ハブで注文のストリームを生成します。GPS 技術を使用して、配送トラックから Azure イベント ハブに緯度と経度の座標が伝送されます。

- リアルタイム ストリーミング データを内部データと統合し、在庫のある最寄りの再販業者を特定して、その再販業者の関係者に注文を準備するよう通知すること。

- 2 つのリアルタイム データ ストリームを組み合わせて、注文があった商品を再販業者から集荷して顧客に配送できる、最も近い場所にいるトラックを 3 台特定すること。注文が処理済みであり、集荷の準備が整っていることを 3 台の配送トラックすべてに通知します。対応可能な最初のドライバーには、注文を速やかに集荷して配送するよう要求が出されます。

- Rapid Delivery Service パイロットのパフォーマンスに関するリアルタイムの分析レポートを意思決定者に提供すること。

Fabrikam は、統合データ プラットフォームとして Microsoft Fabric を採用したばかりです。Fabric には設定なしですぐに使える Real Time Intelligence が備わっていると耳にしたあなたは、Fabric を活用して前述の課題を解決したいと考えています。イベントハウス、KQL データベース、Eventstream を使用して、回復性のある効率的なデータ処理パイプラインを構築します。

# Real-Time Intelligence とリアルタイム ハブ

このセクションでは、Microsoft Fabric に統合された Real-Time Intelligence の機能について説明します。何かを作成するよりも、環境内を見て回ることに焦点を当てます。

## タスク 2: Real-Time Intelligence エクスペリエンスの各項目


1.  Fabric ホーム ページがまだ開かれていない場合は、Power BI サービスの左下隅のアイコンを選択し、\[Fabric\] を選択します。

    ![](../media/Lab-1---April-2026/image15.png)


2.  ホーム画面の Fabric に関する詳細情報のセクションでスクロールして、**Real-Time Intelligence ソリューションを構築する**をクリックします。

    ![](../media/Lab-1---April-2026/image16.png)


3.  新しい Web ブラウザーのタブが開き、Microsoft Learn に移動します。


4.  ドキュメントを見て回ることもできますが、ここでは Microsoft Fabric が表示されているブラウザーのタブに戻ります。


5.  左側のナビゲーション バーから \[ワークロード\] を選択します。

    > ![](../media/Lab-1---April-2026/image17.png)


6.  ワークロード画面で、**Real-Time Intelligence** をクリックします。**自分のワークロード**の下に見つかります。

    ![](../media/Lab-1---April-2026/image18.png)


7.  **Real-Time Intelligence のホーム ページ**が表示されます。このページでは、Real-Time Intelligence に関するサンプル、チュートリアル、ドキュメントが見つかります。


1.  **Eventhouse:** 1 つまたは複数の KQL データベースのワークスペースを作成するために使います。これはプロジェクト間で共有できます。イベントハウス内に KQL データベースも作成されます。


2.  **KQL クエリセット:** データに対してクエリを実行し、共有可能なテーブルとビジュアルを生成するために使用されます。


3.  **リアルタイム ダッシュボード**: タイルのコレクションです。必要に応じてページで整理でき、各タイルは基になるクエリと視覚的表現を持ちます。


4.  **Eventstream:** リアルタイム イベント ストリームのキャプチャ、変換、ルーティングに使用されます。


5.  **Activator:** 変化するデータからパターンや条件が検出されたときに自動的にアクションを実行するために使います。


6.  **イベント スキーマ セット (プレビュー):** イベント スキーマ セットを使用すると、リアルタイム分析ワークフローのデータ構造 (スキーマ) の整理および標準化を支援し、ストリーミング データを一貫して処理および分析するのが容易になります。


7.  **カスタム ストリーム コネクタ (プレビュー):** カスタム ストリーム コネクタを使用すると、独自のカスタム エンドポイントやカスタム アプリから Eventstream にリアルタイム イベントを送信できます。


8.  **Anomaly Detector (プレビュー):** Anomaly Detector は、イベントハウス テーブル内の異常なパターンと外れ値を自動的に識別します。


9.  **オペレーション エージェント (プレビュー):** 手動による監視に頼る代わりに、ユーザーはエージェントを通じて主要なメトリックを継続的に追跡し、提示される的を絞った推奨のアクションを確認できます。明確な目標、指示、データ ソースを設定してエージェントを構成することで、組織全体に複数のエージェントを仮想エキスパートとして展開できます。


10. **マップ (プレビュー):** マップ ビジュアルを使用して、リアルタイム データによる地理空間の分析情報を活用します。


11. **Digital Twin Builder (preview):** デジタル ツイン ビルダーは、オントロジーを通じて、コーディングの経験が浅いまたはまったくないユーザーが、アセットやプロセスなどのビジネス概念を構築してモデル化するのを支援します。

    ![](../media/Lab-1---April-2026/image19.png)

## タスク 3: リアルタイム ハブ


1.  画面左側の Fabric ナビゲーション ウィンドウ内にある**リアルタイム** アイコンをクリックします。

    ![](../media/Lab-1---April-2026/image20.png)


2.  **リアルタイム ハブへようこそ**ダイアログが開き、**ツアーを開始します**または**開始する**を自由に選択できます。

    > ![](../media/Lab-1---April-2026/image21.png)


3.  リアルタイム ハブでは、動いているデータを 1 か所で組織全体にわたってストリーミングできます。すべての Microsoft Fabric テナントは、自動的にこのハブと共にプロビジョニングされます。これを使えば、さまざまなソースから、動いているデータを簡単に検出、インジェスト、管理、利用することができます。


4.  リアルタイム ハブ内では、3 つの異なる種類のデータ統合にアクセスできます。

    - **ストリーミング データ:** これはリアルタイム ハブのホーム ページで、データ ソースをすばやく接続し、データのサンプルをすぐに開始できます。

    - **ビジネス イベント (プレビュー):** 下流のワークフローでアクションを実施するだけの十分な意味のあるイベントを収集します。ビジネス イベントは、重要なビジネス上の意思決定の促進、ワークフローの自動化、アラートのトリガー、分析の有効化、人工知能 (AI) へのリアルタイム コンテキストの提供に役立ちます。この機能により、Fabric で顧客が開始したビジネス イベントの統合ビューが提供されます。

    - **Fabric イベント:** Fabric アーティファクトや外部ソースを介して生成されたイベント。Fabric で利用して、リアルタイム アラートや下流アクションのトリガーなどのイベント駆動型シナリオをサポートできます。Fabric ワークスペース項目のイベントや Azure Blob Storage イベントなど、各種イベントを監視し、対応することができます。

    - **Azure のイベント:** このリストには、ユーザーがアクセスできる Azure で生成されたシステム イベントが含まれています。イベントを監視し、アクティブ化されたときに通知を送信またはアクションを実行するルール セットを設定することができます。

    ![](../media/Lab-1---April-2026/image22.png)


5.  リアルタイム ハブの右側にある **+ データの追加**ボタンをクリックします。

    ![](../media/Lab-1---April-2026/image23.png)


6.  画面に、現在リアルタイム ハブに統合できる各データ ストリームの詳細が表示されます。これには、Azure の各種ソースに加え、Amazon Kinesis、Confluent Cloud Kafka、Google Cloud Pub/Sub などの外部のクラウド ストリーミング ソースも含まれます。
    調査できるサンプル データもいくつかあります。

    ![](../media/Lab-1---April-2026/image24.png)

# ワークスペースとイベントハウスを作成する

## タスク 4: Fabric ワークスペースを作成する


1.  次は、Fabric ライセンスを使用してワークスペースを作成しましょう。左のナビゲーション バーから**ワークスペース**を選択します。


2.  **+ 新しいワークスペース**を選択します。

    > ![](../media/Lab-1---April-2026/image25.png)


3.  **ワークスペースの作成**ダイアログがブラウザーの右側に開きます。


4.  **名前**フィールドに、**RTI_username** を入力します。環境の詳細で提供されたユーザー名を使用します。

    > **注:** ワークスペース名は一意である必要があります。\[名前\] フィールドの下に、**この名前は使用できます**という緑色のチェック マークが表示されていることを確認してください。


5.  必要に応じて、ワークスペースの**説明**を入力できます。このフィールドはオプションです。


6.  **詳細**をクリックしてセクションを展開します。

    > ![](../media/Lab-1---April-2026/image26.png)


7.  **ライセンス モード**で、**評価版**が選択されていることを確認します。(既定で選択されています。)


8.  **適用**を選択して新しいワークスペースを作成します。

    ![](../media/Lab-1---April-2026/image27.png)

    **注: Introducing task flows ダイアログ**が開いた場合は、**Got it** をクリックします。

    ![](../media/Lab-1---April-2026/image28.png)

## タスク 5: イベントハウスを作成する


1.  **+ 新しい項目**ボックスをクリックして、この Fabric ワークスペースに作成できるすべての項目が表示された新しいペインを開きます。

    ![](../media/Lab-1---April-2026/image29.png)


2.  ペイン内の**データの保管**セクションから **Eventhouse** を選択します。前に説明したとおり、これはデータを保存できるという点でレイクハウスと似たものであると考えることができますが、このイベントハウスではリアルタイム ストリーミング データに重点が置かれます。

    ![](../media/Lab-1---April-2026/image30.png)


3.  表示されたウィンドウで、イベントハウスに **eh_Fabrikam** という名前を付け、**作成**をクリックします。

    ![](../media/Lab-1---April-2026/image31.png)


4.  本日の残りのトレーニングでは、最終的にこの場所でさまざまなソースからデータをストリーミングします。項目が作成されるとウィンドウが表示され、イベントハウスに関する詳細が表示されます。**Get started** ボタンをクリックします。

    ![](../media/Lab-1---April-2026/image32.png)


5.  画面に表示される緑色のヒントに従って、イベントハウスの操作を簡単に確認します。最初のヒントは、イベントハウスと共に空の Kusto 照会言語 (KQL) データベースが作成されたことを示しています。

    ![](../media/Lab-1---April-2026/image33.png)


6.  画面上に表示される残りのヒントに従って、追加のデータベースを作成する場所、イベントハウスの OneLake のストレージ、計算時間 (分) での Fabric リソースの使用状況、イベントハウスで発生したアクションを確認します。


7.  イベントハウスの左のナビゲーション ペインで、イベントハウスと一緒に作成された KQL データベースを見つけ、それをクリックしてデータベースの詳細を表示します。

    ![](../media/Lab-1---April-2026/image34.png)


8.  これにより、Fabric ポータルの上部にある 1 つのタブでイベントハウス全体の概要を表示しながら、新しいタブで KQL データベースのプロパティを確認することができます。このシナリオで実現したい目標の 1 つは、KQL データベースにストリーム配信されるデータを、OneLake 経由でアクセスできるようになることです。この機能を実現すれば、この KQL データベース内のデータを、必要な任意のレイクハウスで使うショートカットを通じて簡単に検出できるようになります。右側の**データベースの詳細**セクションを特定し、\[Availability\] オプションを **Enable** に切り替えます。表示されたポップアップ メニューで、Enable を選択します

    ![](../media/Lab-1---April-2026/image35.png)

    ![](../media/Lab-1---April-2026/image36.png)


9.  ブラウザーの左側から **RTI_username** ワークスペースを選択し、開いたペインでもう一度それを選択します。

    > ![](../media/Lab-1---April-2026/image37.png)


10. スペースを最も多く占める**タスク フロー** オプションが表示された場合は、右側の二重上矢印を選択して、そのスペースを最小化します。

    ![](../media/Lab-1---April-2026/image38.png)


11. これで、ストリーミング データを OneLake に取り込み始めるための基本設定が完了しました。次は、この環境で使用可能な動いているデータをキャプチャする Eventstream を作成します。

    ![](../media/Lab-1---April-2026/image39.png)

    > このラボでは、Real-Time Intelligence のインターフェイスを確認し、リアルタイム ハブについて調べ、Fabric ワークスペースを作成して、KQL データベースが付属するイベントハウスを作成しました。次のラボでは、データ資産全体のさまざまなソースから OneLake にデータを取り込む手法を調べていきます。また、Kusto 照会言語 (KQL) を使っていくつかの基本的な分析を行います。
